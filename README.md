# B站视频下载器

粘贴链接就能下载 B 站视频。命令行与网页两个版本，扫码登录，自动取最高清晰度。
可以下整本收藏夹（批量或挑单个），可以顺手带上字幕、弹幕、封面和视频信息。

**只依赖 `requests` 一个库。不需要 ffmpeg，不需要装任何图形库，也不需要 Flask。**

二维码在终端或网页里直接画出来，手机扫一下即可登录。

## 两个版本，按需选用

| 版本 | 入口 | 适合 |
|---|---|---|
| 命令行版 | `python bili_dl.py` | 批量下载、脚本调用、远程终端 |
| 网页版 | `python web_app.py` | 想要界面、拖进度条预览、挑收藏夹里的视频 |

网页版启动后会自动打开浏览器，界面里粘贴链接点一下就行。

两个版本共用同一套下载逻辑（网页版直接引入 `bili_dl.py`），修一处两边都生效，
连配置文件都是同一个（`~/.bili_dl.json`）。网页版同样零额外依赖 ——
界面和 HTTP 服务都用 Python 标准库写的，不需要 Flask，也不需要装任何前端框架。

## 用法

### 交互模式

```
python bili_dl.py
```

启动后会问你要不要扫码登录，然后直接粘贴链接即可，可以连着下多个。
输入 `q` 退出，输入 `dir` 换下载目录。

### 直接下载

```bash
# 完整链接
python bili_dl.py https://www.bilibili.com/video/BV1xx411c7mD

# 只贴 BV 号也行
python bili_dl.py BV1xx411c7mD

# av 号也行
python bili_dl.py av12345

# 短链会自动还原
python bili_dl.py https://b23.tv/xxxxxxx
```

链接里的 `?p=3` 会被自动识别，不用另外加参数。

### 常用参数

| 参数 | 作用 |
|---|---|
| `-p N` | 下载第 N 个分P |
| `--all` | 下载全部分P |
| `-o 目录` | 指定下载目录 |
| `-q 编号` | 指定清晰度，编号见下表 |
| `-t 模板` | 命名模板，见「命名模板」一节 |
| `-y` | 所有确认提示自动通过（脚本里用） |

下载目录默认是 `~/Downloads/BiliVideo`。

### 附加内容

默认只下视频本体。想要字幕、弹幕这些，加对应开关即可：

| 参数 | 作用 |
|---|---|
| `--subtitle` `--sub` | 下载字幕，存成 `.srt`（需要登录） |
| `--danmaku` `--dm` | 下载弹幕，存一份 `.xml`，同时转一份 `.ass` |
| `--cover` | 下载封面图 |
| `--metadata` `--meta` | 存一份视频信息 `.info.json` |
| `--all-extras` `--extras` | 上面四样一次全开 |
| `--audio-only` `--audio` | 只下音频，存成 `.m4a` |
| `--mp3` | 连同音频一起转成 mp3（需要 ffmpeg） |

```bash
# 视频 + 字幕 + 弹幕 + 封面 + 信息，一次拿全
python bili_dl.py BV1xx411c7mD --all-extras

# 当播客听，只要音频
python bili_dl.py BV1xx411c7mD --audio-only
```

产物都放在视频旁边，同名不同后缀：

```
某UP/2026-09-21 某个视频.mp4
某UP/2026-09-21 某个视频.srt          字幕
某UP/2026-09-21 某个视频.xml          弹幕原文件
某UP/2026-09-21 某个视频.ass          弹幕字幕（播放器直接加载）
某UP/2026-09-21 某个视频.cover.jpg    封面
某UP/2026-09-21 某个视频.info.json    视频信息
```

关于字幕：B 站的字幕接口**时好时坏**，同一个视频多请求几次才有。
工具默认重试 5 次，实测 5 次内基本都能拿到。拿不到时会明确告诉你，不会静默跳过。

关于弹幕：`p` 属性里带坐标的高级弹幕（模式 7、8）不转换，它们没有固定轨道，
硬转成一坨滚动字幕反而看不清。原文件 `.xml` 里是完整的，需要时自己去解析。

### 收藏夹

```bash
# 交互式：列出收藏夹 -> 选一本 -> 选视频 -> 下载
python bili_dl.py --fav

# 只列收藏夹和它们的 ID
python bili_dl.py --fav list

# 看某个收藏夹里有什么（列出来，先不下）
python bili_dl.py --fav 1581869426

# 整本下
python bili_dl.py --fav 1581869426 --all

# 挑着下
python bili_dl.py --fav 1581869426 --pick 1,3,5-9

# 按标题关键词筛
python bili_dl.py --fav 1581869426 --search 教程 --all

# 只要 500MB 以下的
python bili_dl.py --fav 1581869426 --all --max-size 500MB

# 大收藏夹先取 200 条看看
python bili_dl.py --fav 1581869426 --limit 200 --all
```

| 参数 | 作用 |
|---|---|
| `--all` `-a` | 下载筛选后的全部 |
| `--pick 1,3,5-9` `-p` | 按序号挑，支持区间 |
| `--search 关键词` `-s` | 只留标题含关键词的 |
| `--max-size 500MB` | 按时长估算体积，滤掉超标的 |
| `--limit N` | 最多取 N 条（大收藏夹很有用） |
| `--list-only` `--dry` `-n` | 只列不下 |

批量下载默认 3 个并发（`concurrency` 可改），每个视频之间隔 1 秒（`interval` 可改）。
并发方面有一件事值得说明：`requests` 的 `Session` **不是线程安全的**，
所以每个任务自己建一个会话。共用会话在高并发下会出现随机的 SSL 错误或响应串包。

**多分P 视频默认只下第 1 个分P**，加 `--all-parts` 才会把每个分P 都下。

### 命名模板

默认存成 `{title}.mp4`。想要整理成目录，用 `-t`：

```bash
# 按 UP 主分目录，文件名带日期
python bili_dl.py BV1xx411c7mD -t "{up}/{date} {title}"

# 带上 BV 号，方便回溯
python bili_dl.py BV1xx411c7mD -t "{up}/{title} [{bvid}]"
```

可用字段：

| 字段 | 含义 |
|---|---|
| `{title}` | 视频标题 |
| `{bvid}` | BV 号 |
| `{aid}` | av 号 |
| `{up}` | UP 主名字 |
| `{date}` | 发布日期，形如 `2026-09-21` |
| `{p}` | 分P 序号，单P 时为空 |
| `{part}` | 分P 名称，单P 时为空 |
| `{quality}` | 清晰度名称 |
| `{duration}` | 时长，形如 `05-32` |

标题里的 `/` 不会变成目录 —— 工具先把模板按 `/` 切开，再往每段里填字段，
最后逐段清理非法字符。这样模板里的目录层级保留，标题里的斜杠被替换掉。

### 配置文件

不想每次都敲参数，可以存成配置：

```bash
python bili_dl.py --show-config              # 看当前配置和可用字段
python bili_dl.py --set template="{up}/{title}"
python bili_dl.py --set subtitle=true
python bili_dl.py --set concurrency=5
```

配置写在 `~/.bili_dl.json`，网页版读的是同一个文件，改一处两边都生效。
可配置的项：`outdir` `quality` `template` `concurrency` `subtitle` `danmaku`
`cover` `metadata` `audio_only` `all_parts` `proxy` `interval`。

配置文件损坏或格式不对时不会报错，直接用默认值 —— 配置坏掉不该让工具完全不能用。

### 清晰度编号

不指定 `-q` 时**自动选择你账号能拿到的最高清晰度**。

| 编号 | 清晰度 | 编号 | 清晰度 |
|---|---|---|---|
| 127 | 8K 超高清 | 80 | 1080P 高清 |
| 126 | 杜比视界 | 74 | 720P60 |
| 125 | HDR 真彩 | 64 | 720P 高清 |
| 120 | 4K 超清 | 32 | 480P 清晰 |
| 116 | 1080P60 | 16 | 360P 流畅 |
| 112 | 1080P 高码率 | | |

```bash
python bili_dl.py <链接> -q 120      # 要 4K
```

指定的档位拿不到时，接口会静默降到你能拿的最高档，工具会把这件事明确告诉你。

### 登录

```bash
python bili_dl.py --login           # 扫码登录，推荐
python bili_dl.py --login-sms       # 手机号短信登录
python bili_dl.py --set-cookie      # 手工粘贴 Cookie 登录
python bili_dl.py --whoami          # 查看当前登录状态
python bili_dl.py --logout          # 清除本机保存的凭证
```

**推荐扫码登录。** 手机上打开哔哩哔哩客户端扫一下终端里的二维码就行，
不用输账号密码，也不涉及验证码。

#### 关于手机号登录

哔哩哔哩的登录接口现在要求先通过极验人机验证。**本工具不会去绕过它** ——
那是官方的反自动化机制。

实际表现是：请求发送短信验证码时，服务器返回 `-105 验证码错误`。
这表示需要先完成人机验证。工具检测到这个返回码后会给出两条路：

- **改用扫码登录**（推荐，一句话的事）
- **手工粘贴 Cookie**：在浏览器里正常登录 B 站，按 F12 打开开发者工具，
  从 Application / 存储 → Cookies → bilibili.com 里复制 `SESSDATA`、
  `bili_jct`、`DedeUserID` 三个值，然后运行 `--set-cookie` 贴进去

少数情况下服务器不要求验证，短信登录就能走通。

## 网页版

```bash
python web_app.py
```

启动后浏览器会自动打开 `http://127.0.0.1:8848`。界面里粘贴链接，点「解析并下载」，
进度条走完就能点链接保存文件。

### 网页版能做什么

- 粘贴链接解析，显示标题、作者、时长、清晰度
- 清晰度下拉按**这个视频实际可用的档位**填充，不是写死的列表
- 实时进度条：百分比、已下/总量、速度
- 下载记录列表，完成后可点链接保存文件
- **支持拖进度条预览**：文件服务实现了 Range 请求，浏览器可以直接播放和拖动
- 页面内扫码登录，二维码直接画在网页上
- **账号收藏夹**：选一本收藏夹载入视频列表，可以勾选多个批量下载，
  也可以点某一行的「下载」单独下那一个
- **附件选项**：字幕、弹幕、封面、元信息、仅音频、多分P 全下，
  和上方的命名模板一起，对单个下载和收藏夹批量都生效
- 批量进度面板：每个视频的百分比、完成、失败一目了然，完成的可以直接点「保存」

### 参数

```bash
python web_app.py --port 9000        # 换端口，默认 8848
python web_app.py --out D:\视频       # 指定下载目录
python web_app.py --no-browser       # 不自动开浏览器
python web_app.py --jobs 4           # 收藏夹批量的并发数，默认读配置，上限 4
```

端口被占用时会自动往后试，不会直接报错退出。

网页版和命令行版共用 `~/.bili_dl.json`：命名模板、清晰度、附件开关都会预填到界面上，
下载目录也一致。

### 为什么网页版要跑一个本机服务

可能有人会问：既然有网页界面，为什么不能做成一个 HTML 文件直接双击打开？

因为纯前端方案在这件事上走不通，有三个绕不过去的坎：

1. **跨域限制**
   B 站的播放地址接口不返回允许跨域的响应头，浏览器里的 `fetch` 会被拦下。
   这是浏览器的安全策略，前端代码没法绕（也不该去绕）。

2. **登录凭证没地方放**
   扫码拿到的 Cookie 必须存在某处。纯前端只能塞进 `localStorage`，
   页面一旦分享出去或换台电脑，凭证就跟着走，很不安全。

3. **大文件下载不可靠**
   浏览器下载几百 MB 的文件，中途断了没法续传，也拿不到稳定的本地路径。

所以这里让本机跑一个小服务：请求由服务端发出（不受跨域限制），
凭证存在服务端用户目录（和命令行版共用同一个文件），
下载由服务端完成并支持断点续传。浏览器只负责显示和触发。

### 安全性

- **只监听 `127.0.0.1`**，外部网络访问不到。除非你显式加 `--host 0.0.0.0`，
  那样同网段其他设备能访问，启动时会给出警告
- **拒绝跨站请求**：会检查 `Origin`，非本机的来源一律 403
- **没有任意文件读取**：取文件接口只接受任务 ID，路径从服务端的任务表里取，
  请求方传什么路径都没用
- **接口不能改下载目录**：请求里的附加选项走白名单，只认模板和几个开关，
  别的键一律忽略；模板长度也做了上限
- **页面上的文字都经过转义**：视频标题来自接口，是不可信输入，
  拼进 HTML 前统一转义，标题里带 `<` 不会把版面拆掉

### 网页版的限制

- **多分P 视频默认只下第 1 个分P**（链接里带 `?p=` 则按它走）。
  要全下，在界面上勾「多分P 全下」
- 收藏夹一次最多提交 500 个视频。再多请分批，或者用命令行版

## 为什么不需要 ffmpeg

B 站同时提供两种播放地址形式：

| 形式 | 内容 | 需要 ffmpeg |
|---|---|---|
| 已合并 MP4（接口参数 `fnval=1`） | 音视频在同一个文件里 | **不需要** |
| DASH 分轨 | 视频轨与音频轨分开 | 需要 |

工具**默认请求已合并的 MP4**，所以下载下来就是能直接播放的完整文件。
实测在多个视频上均可用。

遇到只有 DASH 的视频时，会分别下载视频轨与音频轨，并自动查找 ffmpeg 合并。
找不到 ffmpeg 也不会失败，会保留两个文件并告诉你该怎么用播放器分别加载。

## 功能

- **断点续传**   中断后重跑，从已下载的位置继续
- **多分片拼接**  视频分成多个片段时自动下载后拼接
- **进度显示**   实时显示百分比、已下载量、总大小与速度
- **文件名清理**  自动去掉 Windows 不允许的字符，避免保存失败
- **自动清晰度**  登录后自动选到账号允许的最高档
- **已存在跳过**  同名文件已下载过就直接跳过
- **收藏夹下载**  整本批量下，或按序号、关键词、体积筛选后挑着下
- **附加内容**    字幕、弹幕（含 ASS 转换）、封面、视频信息
- **只要音频**    直接取音频轨，不浪费带宽下视频
- **命名模板**    按 UP 主、日期、清晰度等字段自动整理目录
- **配置文件**    常用设置存一次，命令行和网页两个版本共用

| 4 | 安全防护：路径遍历、跨站请求、超大请求体、无效链接 |
| 5 | 并发：8 个并发下载 + 多线程轮询状态 |
| 6 | 任务管理：ID 生成、进度计算、除零、数量上限 |
| 7 | 辅助函数与字节计数 |
| 8 | 命令行入口，含端口占用时自动换端口 |

网页版的文件服务测试用**注入假任务**的方式做，因此完全离线、可反复跑，
不受 B 站接口波动影响。

### 浏览器端到端

`test_web_browser.py` 会启动一个真实的 Edge（无头模式），通过 CDP 协议操作页面：
填入链接、点击按钮、等待下载、读取界面文字，然后载入收藏夹、全选、批量下载，
再检查批量面板有没有跑到结束。

它验证的是**接口测试覆盖不到的东西**——按钮点击事件有没有绑对、
进度条有没有真的动、全选之后按钮上的数字对不对、完成后链接有没有出现。

```
python -m pip install websockets     # 跑这个测试才需要
python test_web_browser.py
```

页面在测试期间会装一个 `window.__errs` 收集器，任何 JS 报错或未处理的
Promise 拒绝都会让最后一组测试红掉。

### 稳定性压测

主套件用了不少构造数据，可能掩盖真实环境里的问题。压测这组刻意不走 mock：

- 接口返回脏数据（清晰度列表混入字符串与 None、缺 owner 字段、缺标题）
- 下载中途抛 `ConnectionError` / `ChunkedEncodingError` / `Timeout`
- 非交互环境下 stdin 立即 EOF
- 只读命令是否会产生创建目录这类副作用
- 各种函数收到类型不对的参数

端到端那组还会**真的跑一遍下载与续传**：下到 400 字节断开，第二次带上
`Range: bytes=400-` 只补剩余部分，最后逐字节校验成品内容与预期完全一致。

`test_shutdown.py` 专门验证服务停止时不等在跑的请求：造一个卡住 30 秒的请求，
然后关服务，要求 3 秒内退出来（实测 0.23 秒）。

### 二维码编码器的验证

二维码部分是纯 Python 自己实现的，没有引第三方库。验证方式不是与别的库比对矩阵，
而是把生成的码画成像素图，交给 **OpenCV 的独立解码器**读回来对内容。

```bash
python -m pip install opencv-python-headless numpy
python test_qr.py
```

之所以不比对矩阵：不同实现可以选不同的掩码，两种都合法，比了说明不了对错。
只有能被独立解码器读出来的才算正确。

## 已知限制

- **手机号短信登录大概率走不通**，原因是官方要求人机验证，见上文说明。
- **付费番剧与会员专属内容不下载**，这是有意为之，不是缺陷。
- **不保证所有视频都能下**。创作者关闭下载、视频被设为私密、地区限制等情况都会失败。
- **字幕接口时好时坏**。同一个视频多请求几次才有，工具已内置重试。
- **收藏夹一次最多提交 500 个视频**（网页版）。再多请分批或用命令行版。
- **多分P 视频默认只下第 1 个分P**，要全下得显式打开开关。
  收藏夹接口只给"分P 总数"，给不出"第几分P"，所以没法在批量里逐P 挑。
- 接口是哔哩哔哩的公开网页接口，将来若变更，工具需要相应更新。

## 常见问题

**登录了，为什么还是 1080P？**

清晰度上限由你的账号权限和视频本身共同决定，两样缺一不可。

- 视频本身最高只上传到 1080P，那谁都拿不到更高
- 视频有 4K，但需要大会员，而你不是，那也只能到 1080P

工具会把实际拿到的档位和本账号可用档位都告诉你。看到
「本账号对该视频最高可到 XXX」，那个 XXX 就是你这个号的天花板。

**扫码后手机提示登录成功，但终端还显示等待扫码？**

手机 App 上还需要点一次「确认登录」。二维码有效期内都可以。

**提示"二维码绘制失败"怎么办？**

不影响使用。二维码下面会直接给出那条链接，把它发到手机浏览器打开，效果一样。

**下载到一半断了怎么办？**

直接重跑同样的命令。工具用 `.part` 文件记录进度，会从断点继续。
下载过程中的文件名是 `xxx.mp4.part`，全部拿完才改成 `xxx.mp4`，
所以看到 `.part` 就说明还没下完。

**能不能下付费番剧 / 会员专属内容？**

不能，这是有意为之。工具不绕过任何付费或权限校验。

**为什么有些视频会提示需要 ffmpeg？**

少数视频 B 站不提供已合并的 MP4，只有 DASH 分轨。
这时工具会分别下载视频轨和音频轨，再找 ffmpeg 合并。
没装 ffmpeg 也不报错，两个文件都会留着，用播放器分别加载即可。

**下载的文件名里为什么有 `[P1]` 这种字样？**

多分P视频给每个分P单独命名，否则它们会互相覆盖。

**收藏夹里明明有视频，为什么显示的数量对不上？**

收藏夹里已经失效的稿件会被剔除，所以你看到的比网页上显示的少。
两种失效形态都会认：接口不给 bvid 的，以及 bvid 还在但标题被替换成
「已失效视频」之类的。后者不提前剔除的话，下载时会白跑一次请求再报失败，
几百个的批量里会攒出一堆假失败。

**勾了字幕但没下到 `.srt`？**

B 站的字幕接口不稳定，同一个视频多请求几次才有。工具已经重试 5 次，
5 次都没拿到就说明这个视频此刻确实取不到字幕，换个时间再试可能就有了。
没有字幕时不生成空的 `.srt` 文件，避免留下一个看起来正常的空文件。

**为什么有些弹幕没出现在 `.ass` 里？**

带坐标的高级弹幕（模式 7、8）没有固定轨道，转成滚动字幕会挤成一团，
所以跳过不转。完整的弹幕在旁边的 `.xml` 里，一行不少。

**下载到一半按 Ctrl+C，为什么要等一会儿才退出？**

现在不会等了。服务停止时不会去等在跑的请求，会立刻退出；
没下完的部分留在 `.part` 文件里，下次运行接着下。

**会封号吗？**

工具没有做任何破解，请求特征和网页端一致。但**请勿高频批量抓取** ——
那不管用什么工具都可能触发风控。正常自己看视频的量级没有问题。

收藏夹与附件，两个版本一起补齐。

新增

- **命名模板**：`-t "{up}/{date} {title}"`，共 9 个可用字段
- **配置文件**：`~/.bili_dl.json`，`--show-config` / `--set key=value` 管理，
  命令行版和网页版共用
- **网页版收藏夹界面**：收藏夹下拉、视频列表带勾选框、全选/清空/反选、
  每行独立的「下载」按钮、批量进度面板
- 新增 `test_fav.py`（199 项）与 `test_shutdown.py`

修掉的问题

- **多分P 视频会被下错分P**。收藏夹接口里那个叫 `page` 的字段是"分P 总数"，
  不是"第几分P"，之前被当成了下标，于是所有多P 视频都只下了最后一个分P。
  实测 `BV15J41187T2` 该字段返回 2，视频信息接口给出的 `pages` 也正好是 2 个。
  现在改名成 `parts`，只用来显示"共几P"
- **后台下载线程会永久卡死**。多分P 视频会问"下哪个分P"，网页版在终端里启动时
  `sys.stdin.isatty()` 是 True，于是后台线程真的去调 `input()`，
 没人回答就一直等 —— 网页上表现为进度条停在 0%，也不报错。
  现在改成由入口显式声明 `set_interactive()`，不再靠 `isatty()` 猜
- **网页版 `re` 没有导入**，收藏夹下载一律 `NameError`
- **`--max-size 500MB` 会被静默忽略**。只认单字母后缀，`500MB` 判成认不出来返回 0，
  而 0 表示"没设上限"，于是筛选完全没生效。现在认 `B/KB/MB/GB/TB` 各种写法，
  认不出来时也会明确说一声
- **按 Ctrl+C 停网页版要等大文件下完**。`ThreadingHTTPServer` 默认
  `block_on_close=True`，关闭时会 join 所有请求线程。现在关掉这个行为，
  实测有请求卡住时关闭耗时从 30 秒降到 0.23 秒
- **批量任务的下完文件点不开**。取文件接口只查单视频任务表，
  批量的每一项都不在里面。现在会再去批次里找
- **附件类型一律写成 `video/mp4`**，音频和字幕会拿错误的程序打开。改为按扩展名推断
- **视频标题里的 `<` 会拆掉版面**。标题来自接口，是不可信输入，
  拼 `innerHTML` 前现在统一转义
- **浏览器取消请求会在终端刷调用栈**。`ConnectionResetError` / `BrokenPipeError`
  是浏览器频繁刷页面时的正常现象，现在不当成程序错误
- **favicon 的 404 日志**。改为返回 204 且不记日志
- **批量下载时控制台被刷满**。静默模式下 `info`/`step`/`ok` 不再输出，
  分P 列表也不再逐条打印；`warn`/`err` 照常

修掉的两个问题：

- **越界 Range 会让客户端永久挂住**。416 响应漏发 `Content-Length`，

  残留字节会被当成下一个请求的开头。现在一律读完再拒绝（413）
